# NotchMirror

Маленькая «чёлка» вверху экрана: наводишь курсор — раскрывается панель с живым видео с камеры,
направленной **за спину**. Как зеркало заднего вида в машине, только на мониторе.

![Панель с камерой](docs/panel.png)

## Что уже работает

- **Чёлка** по центру верхнего края экрана, поверх всех приложений, клики проходят сквозь неё.
- **Раскрытие по наведению** (120 мс задержки, чтобы не открывалась случайно) и сворачивание
  с задержкой 420 мс, чтобы не мигала.
- **Панель с видео**: источник, кнопки «закрепить», «зеркалить», «настройки», «свернуть».
  Кнопки срабатывают по нажатию и **не забирают фокус** у приложения, в котором вы работаете.
- **Три источника видео** на выбор (см. ниже), переключаются в настройках.
- **Зеркалирование** картинки как у настоящего зеркала + поворот на 180° для телефона.
- **Трей**: показать/скрыть чёлку, пауза камеры, автозапуск, выход.
- **Горячая клавиша** `Ctrl+Alt+M` — показать/скрыть панель без наведения.
- **Автоскрытие** в полноэкранных приложениях (игры, видео, презентации).
- Камера выключается через 20 с простоя (индикатор камеры гаснет), либо её можно держать
  включённой для мгновенного раскрытия — переключатель в настройках.

## Источники видео: как получить «картинку за спиной»

Встроенная камера ноутбука смотрит **на вас**, поэтому «зеркала заднего вида» из неё не выйдет.
Нужна камера, направленная назад. Поддерживаются все варианты:

| Вариант | Что нужно | Задержка | Как выбрать |
|---|---|---|---|
| **Внешняя USB-вебка** на кронштейне над монитором, объективом от себя | камера ~1500–3000 ₽ | 30–60 мс | «Локальная камера» → устройство |
| **Телефон как камера Windows** (Phone Link, Windows 11 24H2+) | телефон + подключение в приложении «Связь с телефоном» | 100–250 мс | «Локальная камера» → в списке появится модель телефона |
| **Телефон как IP-камера** (IP Webcam, DroidCam) | приложение на телефоне, общий Wi-Fi | 100–300 мс | «Телефон / IP-камера по сети» + адрес вида `http://192.168.1.42:8080/video` |
| Встроенная камера (если «назад» не нужно) | — | 30–60 мс | «Локальная камера» → камера по умолчанию |

Панель «Источник видео» в настройках показывает живое превью, по нему удобно наводить камеру.

## Требования

- Windows 10 (сборка 19041+) или Windows 11, x64.
- .NET 9 **Desktop Runtime** для запуска (или self-contained сборка, см. ниже).
- Для сборки из исходников — .NET 9 SDK (скрипт `setup-sdk.ps1` поставит его локально).

## Быстрый старт

```powershell
powershell -ExecutionPolicy Bypass -File setup-sdk.ps1   # один раз: .NET SDK в .tools (без админа)
powershell -ExecutionPolicy Bypass -File build.ps1       # сборка
powershell -ExecutionPolicy Bypass -File run.ps1         # запуск
```

Приложение появляется в трее. Чёлка — вверху по центру. Первый запуск открывает настройки
кнопкой в трее или повторным запуском `run.ps1` (второй экземпляр не запускается, а открывает
настройки уже работающего).

Сборка одного exe для раздачи:

```powershell
powershell -ExecutionPolicy Bypass -File publish.ps1                 # один exe ~25 МБ, нужен .NET 9 Desktop Runtime
powershell -ExecutionPolicy Bypass -File publish.ps1 -SelfContained  # ~120 МБ, ничего не требует
```

## Управление

- **Наведение на чёлку** — раскрыть панель.
- **Кнопки на панели**: закрепить (не сворачивается), зеркалить, настройки, свернуть.
- **`Ctrl+Alt+M`** — показать/скрыть панель.
- **Трей**: пауза камеры, автозапуск, показ чёлки, выход.

## Настройки

Файл: `%AppData%\NotchMirror\settings.json` (если профиль недоступен для записи, приложение
уходит в `%LocalAppData%\NotchMirror` или в `userdata` рядом с exe). Там же `app.log`.

Что настраивается: источник и устройство камеры, адрес MJPEG-потока, зеркалирование и поворот,
размер панели (3 пресета), прозрачность чёлки, клики сквозь чёлку, скрытие в полноэкранных
приложениях, исключение из скриншотов, автозапуск, «держать камеру включённой», монитор,
горячая клавиша.

## Как это устроено

```
src/NotchMirror
├── App.xaml(.cs)            запуск, единственный экземпляр, трей, лог
├── Ui/MainWindow            оверлей-чёлка и панель
├── Ui/SettingsWindow        окно настроек с превью
├── Cameras/
│   ├── CameraController     единая точка доступа, состояния, сообщения об ошибках
│   ├── LocalCameraSource    Media Foundation (WinRT MediaCapture + MediaFrameReader)
│   ├── MjpegCameraSource    MJPEG/JPEG по HTTP для телефона
│   └── CameraDevices        перечисление камер
├── Services/                настройки, автозапуск, хоткей, трей, fullscreen-watcher
└── Interop/Native.cs        Win32 P/Invoke
```

Технические решения, которые пришлось принять (и грабли, на которые легко наступить):

1. **WPF-окно с `AllowsTransparency=true` нельзя трогать через `SetWindowLong(GWL_EXSTYLE)`**:
   это сбрасывает layered-атрибуты, и окно становится невидимым, хотя `IsWindowVisible = true`
   и содержимое рисуется. Поэтому «не забирать фокус» сделано через
   `WM_MOUSEACTIVATE → MA_NOACTIVATE`, а отсутствие кнопки в панели задач — через
   `ShowInTaskbar=false`.
2. **Клики сквозь окно** — хук `WM_NCHITTEST`, который возвращает `HTTRANSPARENT` вне панели.
   Окно большое и постоянное, поэтому нет ресайза при раскрытии и мерцания.
3. **Наведение определяется опросом `GetCursorPos`** (25 Гц), а не событиями мыши: работает
   даже когда чёлка полностью «прозрачна» для кликов.
4. **Клип скруглённого видео** нужно пересчитывать на `SizeChanged` контейнера, иначе
   `RectangleGeometry.Rect` остаётся пустым и видео обрезается целиком.
5. **Кодировка исходников**: на русской Windows компилятор читает файлы без BOM как CP1251.
   В проекте задан `<CodePage>65001</CodePage>`, а `.cs` сохранены с BOM.
6. **Кнопки панели срабатывают по `PreviewMouseLeftButtonDown`, а не по `Click`**: оверлей
   намеренно не активируется (`WM_MOUSEACTIVATE → MA_NOACTIVATE`, чтобы не уводить фокус),
   а `ButtonBase` без активного окна не может захватить мышь — и `Click` не приходит.
7. **Геометрия для наведения и hit-теста считается из прямоугольника окна** и констант
   раскладки, а не из WPF-элементов: так она не зависит от анимаций, `RenderTransform`
   и `ActualWidth`.
8. **DPI**: приложение per-monitor v2, позиция считается в физических пикселях через
   `GetDpiForMonitor`/`SetWindowPos`.
9. **Камера**: `MediaCapture` с `MemoryPreference.Cpu`, кадры `SoftwareBitmap` → BGRA32 →
   `WriteableBitmap.WritePixels`. Ошибки доступа (`E_ACCESSDENIED`) превращаются в понятный текст
   про «Параметры → Конфиденциальность → Камера».

## Если что-то не работает

1. **Камера не включается.** В панели и в настройках показывается точная причина и код ошибки.
   Кнопка «Скопировать диагностику» в настройках кладёт в буфер отчёт: список камер, состояние,
   путь к логу, разрешение камеры в реестре — его удобно прислать.
2. **Запускайте `NotchMirror.exe` обычным двойным кликом.** Если запускать приложение из
   ограниченного окружения (песочница, некоторые IDE и агенты запускают процессы с урезанным
   токеном), Windows может запретить доступ к камере — тогда любая камера вернёт «Отказано в доступе».
3. **Камеру занял другой процесс.** Phone Link (режим «телефон как веб-камера»), Zoom, Teams и
   виртуальные машины с пробросом USB часто держат камеру монопольно. Приложение перебирает
   доступные камеры и возьмёт первую свободную; в настройках можно выбрать конкретную.
4. **Автозапуск.** Если путь к exe изменился, снимите и снова поставьте галочку «Запускать
   вместе с Windows».

Диагностический запуск из консоли (пишет отчёт в лог и выходит):

```powershell
.\NotchMirror.exe --selftest      # геометрия окна, hit-test, список камер, попытка включить камеру
.\NotchMirror.exe --panel-test    # то же, но панель закреплена и остаётся открытой 10 секунд
```

## Ограничения

- Чёлка видна поверх обычных окон и borderless-фуллскрина, но **не поверх эксклюзивного
  полноэкранного режима** (так устроен DWM) — такие приложения лучше запускать в borderless.
- **Индикатор камеры горит, пока устройство открыто.** Отсюда два режима: «экономный»
  (включение по наведению, 0.5–1 с) и «тёплый» (мгновенно, но индикатор горит всегда).
- Если камеру занял Zoom/Teams/Phone Link, приложение покажет это в панели, а не чёрный экран.
- MJPEG-поток требует общей сети с телефоном; для IP Webcam обычно
  `http://<ip>:8080/video`, для DroidCam — `http://<ip>:4747/video`.

## Разработка

- Проект один: `src/NotchMirror/NotchMirror.csproj` (WPF, `net9.0-windows10.0.19041.0`).
- Внешних NuGet-зависимостей нет: камера — Media Foundation через WinRT-проекции, MJPEG —
  свой парсер на `HttpClient`, трей — `NotifyIcon` из WinForms, иконка рисуется в рантайме.
- Логи: `%AppData%\NotchMirror\app.log` (дублируются в stderr, если запускать с перенаправлением).
